The Idea

It started with a gift. Someone handed me a squishy butter toy and I immediately understood why people were obsessed with them.

Physical squishies were selling out at fairs and people were queueing for restocks. If people were this excited about a foam rectangle that does nothing, a digital version with real physics, a collection mechanic and something to show for it could work.

But almost every squishy thing on the web is a scale animation: the object shrinks toward its middle and springs back, and it feels like rubber. I wanted the feeling of a fingertip actually sinking into something soft. That's a materials problem, not an animation problem, so it needed a real deformation model running on the graphics card. The squish counter was deliberate too. Knowing you've squeezed something 12,000 times makes it yours.

One Squish Engine, 214 Skins

Four decisions do most of the work, and you notice each one in the first three seconds without being able to name it.

  • Jab it and it resists. Lean on it and it gives. Resistance rises with the square of how fast you're pressing, which is what separates memory foam from rubber.
  • Hold it and it keeps giving. The target depth drifts lower the longer your finger stays down, so the butter never hits a wall and stops.
  • Let go and the dent stays. It sits for a couple of seconds, then eases back without bouncing. A spring would overshoot, and overshoot is exactly what reads as jelly.
  • Press in several places at once. Every dent is its own little simulation, and each fades on its own schedule.

Deformation runs in a GLSL vertex shader. The CPU evolves each dent's depth and velocity every frame and uploads them; the GPU only does the geometry math. The number of dents is compiled into the shader, and asking for too many makes it silently fail on lower-end hardware, which renders as a blank canvas. So before compiling, the engine asks the device what it can afford:

const budget = gl.getParameter(gl.MAX_VERTEX_UNIFORM_VECTORS) || 128; // each dent slot costs ~2.75 vec4 uniforms const affordable = Math.floor((budget * 0.45) / 2.75); const cap = isMobile ? 20 : 48; return Math.max(6, Math.min(cap, affordable));

The phone cap is 20 because 48 was measurably slower on iOS.

148 of the skins are also bundled iMessage stickers. Hover to pause the lineup.

A skin is data plus a look: a compressed texture map, or for around 50 skins a generator that paints it at runtime, plus its own material, physics and sound. The same engine, shaders, sound model and certificate system drive all of them, so adding a skin means describing it, not building a new feature. That's what made a 214-skin catalogue practical for one person.

Some skins push the engine further. Frozen barely yields until you warm it, and it warms where you touch it, so one end can soften while the rest stays solid. Fur is 16 stacked shell layers, each run through the squish shader so the coat dents with the butter. Gold reflects the actual room instead of painted highlights. Sound is generated live in Web Audio and fed the dent's depth and speed every frame, so it tracks what your hand is doing.

The Pull System and Its Economy

Blind bags and mystery boxes were already dominating toy retail (Stanley cups, Sonny Angels, Pop Mart figures), and the same mechanic was proven in mobile games. Nobody had applied it to a browser-based tactile toy, and a butter you discover through a pull feels different from one you pick off a shelf.

You buy coins, then spend them on pulls that draw from the full rarity pool with published odds. You never pull a butter you already own. An Epic or better is guaranteed within 30 pulls and a Legendary within 90. New accounts start with 300 coins, enough for three pulls, and each pull ends in a card reveal keyed to the rarity you got. Every skin carries a serial number, a provenance story, a certificate and a trading card.

Pulls run entirely on the server. One Postgres transaction locks the player's row, deducts the coins, applies the pity counters, draws only from skins the player doesn't own, assigns the next serial and refuses the pull if a limited skin has sold out. All or nothing. The client never decides what you get or how many coins you have.

Before a release I audited the economy end to end and found real holes. A server-only function that credits purchases had never had its default public access revoked, so in principle anyone with the public API key could grant themselves coins. And because players could edit their own profile row, they could reset the last daily claim and collect the same reward again. One migration locked every coin-granting function to the server and turned the profile guard from a block-list into an allow-list. Purchases are now capped by what the store actually reports, so a fabricated transaction ID can't mint coins.

To test that without touching real players, I rebuilt the backend so a complete local copy comes up with one command, seeded with the full catalogue and test accounts. Now more than 250 SQL tests cover pulls, payments, permissions, consent and account deletion, 105 more run the server functions against forged and replayed store receipts, and 500 Vitest tests cover the game code. One command runs every suite locally before each push. The tests found four more real bugs, all fixed and deployed the same day, each with the test that proves it: limited skins could sell past their supply cap, two players pulling at the same instant could get the same serial number, buying the same coin pack on Mac and then iPhone didn't credit the second one, and a web bank transfer was credited before the money arrived.

What Was Hard

Getting the feel right was mostly deleting things that were subtly wrong: a spring on release, a dent that never deepened, a drag that slid one divot around instead of leaving a trail. Each was defensible on its own, and each made the butter feel like a different material.

The worst bug looked correct in the code. The spacing check measured the gap between the cursor and the active dent, but that dent eases toward the cursor every frame, so the distance never grew large enough to trigger. Below a certain speed, dragging left no trail at all. Simulating the loop outside the browser found it in one pass.

Payments are live everywhere: Stripe on the web, App Store and Google Play purchases verified on the server. Android launched September 16 with no paid promotion, and Google Play's recommendation rows did the rest. Almost all of that traffic came through browse surfaces rather than search: people install an interesting icon, and only about a third open it. The ones who do stick around, and signed-in players come back about three times as often. The next experiments are store listing keywords to earn search traffic and a first-launch nudge to close the gap between install and open.

What I'd do differently. Set up a local database from day one; for months every change was tested against the live project. Treat the economy as adversarial from the first coin, because every hole I closed came from trusting the client somewhere. And ask for sign-in later. Guests can now squish freely and see a sign-up nudge after 25 squishes; letting them try a pull first is the next experiment.

Auth

Sign in with Apple, Sign in with Google, or an eight-digit email code - no password to forget or rotate. The magic link pattern was ruled out early: a tapped link that opens a new browser tab breaks the flow, and the right email client on iOS isn't guaranteed to match the browser. A one-time code sidesteps both problems - the user stays in the same app, on the same page, and nothing depends on which client they open.

Once you're in, your profile tracks coins, squish count, and total time squished. You can set a username, pick your butter's color from 38 options, choose from 59 expressions, and claim a title - starting with Fresh Out the Fridge and unlocking through Squish Enthusiast, Butter Baron, and beyond as your squish count, time, and collection grow.

Four Languages

About 69% of players use Indonesian, Spanish or Portuguese, so an English-only app was talking past most of its audience. In October I translated all of it into those three languages. The interface shipped on October 22, and the written lore for all 214 skins, the provenance stories on every certificate and trading card, went live on October 23. Widgets, iOS permission prompts, push reminders and the store listings are translated too.

The lore was the big piece: about 5,000 lines per language. Longer Spanish and Portuguese strings also broke layouts that fit in English, so the certificate stamp and footer had to be refitted for phones. To keep that from coming back, a screen smoke test runs 104 checks across all four languages at two viewport sizes, alongside the Vitest unit suite.

The store art followed. The screenshot pipeline takes a language flag, loads the app in that language and sets the headlines in it, so each translated listing gets the app the way those players see it: 120 localized screenshots across iPhone, iPad, Android and Mac.

Beyond the Phone

The same account follows you off the main screen: home-screen and Lock Screen widgets show your squish stats, the Apple Watch app keeps your count on your wrist, and 148 butters ship as iMessage stickers bundled with the app.

Squishy Butter in VR: Vision Pro, Quest and Android XR

Open squishybutter.app in the headset's browser and tap Enter Immersive. The butter sits at real size, about 12 cm, on a counter a metre off the floor, close enough to reach. Pinch to squish: the pinch is cast as a ray onto the butter and pressed exactly like a fingertip, so the same GPU dents, sounds and skins carry over. You can also pick the butter up, carry it and set it back down, and a small sign on the counter switches between five themed rooms without leaving immersive mode.

It's WebXR in the browser, so there's no native port and no separate app to install. A native Vision Pro wrapper was prototyped and dropped, because WebXR doesn't run inside a WKWebView. An automated test drives the whole flow in an emulated Quest headset: enter, squish, lift, move, and cycle every room.
